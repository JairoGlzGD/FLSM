01Conceptos Básicos

Antes de calcular, es fundamental dominar estos conceptos:

📡

Dirección IP

Número de 32 bits dividido en 4 octetos que identifica un dispositivo en la red. Se escribe en notación decimal punteada, como 192.168.5.10.

🎭

Máscara de subred

Número de 32 bits que separa la porción de red de la porción de host. Los bits en "1" identifican la red; los en "0", los hosts.

📍

Notación CIDR

Forma compacta de expresar la máscara. /24 indica que los primeros 24 bits son de red. Equivale a 255.255.255.0.

📢

Broadcast

Última dirección de cada subred. Se envía a todos los hosts de esa subred. No puede asignarse a ningún dispositivo individual.

🔒

Dirección de red

Primera dirección de la subred. Identifica a la subred misma y tampoco puede asignarse a hosts. La porción de host es todo ceros.

⚡

FLSM

Fixed Length Subnet Mask: todas las subredes generadas tienen exactamente la misma máscara y la misma cantidad de hosts. Es el método más sencillo y estructurado.

02Guía de 5 Pasos FLSM

🎯 Problema: Red 192.168.5.0/24 — se necesitan 5 subredes con al menos 30 hosts cada una.

Paso 1

Identificar los datos del problema

Red original: 192.168.5.0
Prefijo: /24 → máscara 255.255.255.0
Total de IPs disponibles: 28 = 256
Subredes necesarias: 5
Hosts mínimos por subred: 30
💡 Con /24, el cuarto octeto está completamente disponible para subneteo.
Paso 2

Calcular los bits de subred (n)

Aplicamos la fórmula: 2n ≥ número de subredes

Bits (n) 2n ¿Suficiente para 5?
n = 12✗ No
n = 24✗ No
n = 38✓ Sí
💡 Con n = 3 bits obtenemos 8 subredes posibles. Necesitamos 5, quedan 3 de reserva.
Paso 3

Calcular la nueva máscara

Prefijo original: /24
+ Bits prestados (n): + 3
Nueva máscara: /27
En decimal: 255.255.255.224

Hosts por subred: 2(32 − 27) = 25 = 32 direcciones

✅ Hosts utilizables = 32 − 2 = 30 hosts (cumple el requisito)

24 bits de red
3 bits
5 bits de host

Total: 24 + 3 + 5 = 32 bits

Paso 4

Calcular el incremento (salto de red)

El incremento indica cuánto avanza la dirección de red en cada subred:

Incremento = 256 − valor del último octeto de la máscara
Incremento = 256 − 224 = 32

Las redes saltan de 32 en 32 en el cuarto octeto:

192.168.5.0
+32 →
192.168.5.32
+32 →
192.168.5.64
+32 →
192.168.5.96
… →
192.168.5.224
Paso 5

Determinar rangos: hosts y broadcast

🔒
Dirección de red: el valor de inicio del salto
▶
Primer host: Dirección de red + 1
◀
Último host: Broadcast − 1
📢
Broadcast: (Siguiente red) − 1

Ejemplo — Primera subred (192.168.5.0/27):

Red:192.168.5.0
Primer host:192.168.5.1
Último host:192.168.5.30
Broadcast:192.168.5.31

05Errores Frecuentes

❌

No restar 2 a las direcciones

Muchos confunden el total de IPs con los hosts utilizables. Siempre resta la dirección de red y el broadcast: hosts útiles = 2n − 2.

❌ /27 tiene 32 hosts ✅ /27 tiene 30 hosts útiles
🔢

Calcular mal el incremento

El incremento NO se toma del prefijo CIDR directamente. Se calcula como 256 menos el último octeto de la máscara decimal.

❌ /27 → incremento 27 ✅ 256 − 224 = 32
🎯

Confundir octeto afectado

El incremento debe aplicarse sobre el octeto que cambia según la nueva máscara. Para /27, el octeto afectado es el 4.°; para /18, el 3.°.

💡

n insuficiente para las subredes

Asegúrate de que 2n sea mayor o igual al número de subredes. Con n = 2 obtienes 4, que no es suficiente si necesitas 5 o más.
